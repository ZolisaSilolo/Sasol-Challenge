# Sasol Customer Value Recruitment Challenge

Leak-free, multi-cohort, three-head pipeline for the Sasol Customer Value challenge, run locally or on Google Cloud from VS Code. No AutoML: LightGBM, CatBoost, XGBoost, scikit-learn, scipy and sentence-transformers only. Global seed is 42.

## Targets

| Target | Definition |
|---|---|
| `CLV_fuel` | `ln(1 + litres) / 2.352825386185113` over the next 3 calendar months |
| `CLV_nonfuel` | `ln(1 + rand) / 2.4200904988927476` over the next 3 calendar months |
| `Opportunity` | one of the 17 classes in `label_config.json`, generated by `label_rules.py` |

Tracked metrics: RMSE fuel (w=0.3), RMSE non-fuel (w=0.3), weighted F1 Opportunity (w=0.4), plus
`composite_loss = 0.3·RMSE_f + 0.3·RMSE_nf + 0.4·(1 − F1)` (lower is better).

## Layout

```text

src/features.py              Polars RFM / momentum / IPI / per-category / cadence features (rows < cutoff only)
src/embeddings.py            sentence-transformer on UNIQUE item texts -> SVD(16) + 17-class affinities
src/models/gbdt.py           LGBM / CatBoost (GPU) / XGBoost (cuda) wrappers, auto device
src/models/hurdle.py         P(z>0) x E[z | z>0] hurdle for CLV_nonfuel
src/pipeline.py              cohorts, OOT benchmark, GroupKFold, 3-head OOF stack
src/postprocessing.py        simplex blending + nested-OOF class multipliers in [0.2, 5]^17
src/submission.py            pre-flight submission assertions (also a CLI)
scripts/gcp_cluster.sh       GCP lifecycle (Makefile wraps it); remote_*.sh run on the VM
archive/colab/               retired Colab workflow, kept for reference
tests/                       41 tests on synthetic data through the real label_rules.py
```

## Method

- Cohorts: the five organiser `calibration_cutoffs` (2024-09-01 … 2025-09-01). Features use `ts < cutoff`, targets use `[cutoff, cutoff + 3 months)`, and labels are byte-identical to `label_rules.py` (tested).
- Validation:
  - Out-of-time: train on cohorts whose outcome window ends on or before 2025-09-01, then score the 2025-09-01 cohort.
  - Final fit: 5-fold `GroupKFold` grouped on customer `ID` across all pooled cohorts.
- Head 1 (fuel): LGBM, CatBoost and XGBoost on RMSE, plus an auxiliary LGBM Huber model, simplex-blended on OOF and clipped at 0.
- Head 2 (non-fuel): direct LGBM, CatBoost and XGBoost, plus a calibrated hurdle model (P(z>0) classifier × positive-only regressor), blended on OOF and clipped at 0.
- Head 3 (Opportunity):
  - Inputs: the base features plus OOF-only meta-features from Heads 1–2 (ẑ_fuel, ẑ_nonfuel, P(z>0), and predicted deltas vs the previous quarter). Test rows get fold-averaged predictions instead.
  - Models: LGBM, CatBoost and XGBoost probabilities blended on log-loss.
  - Post-processing: nested-OOF class multipliers, `argmax_c(w_c · P_c)`. These fall back to plain argmax when they don't help on held-out folds.

Current real-data result (`fast_config`, 4-core CPU, 23 min):

| | RMSE fuel | RMSE non-fuel | wF1 | composite loss |
|---|---|---|---|---|
| OOT @ 2025-09-01 | 0.5995 | 0.7441 | 0.5093 | 0.5993 |
| Grouped 5-fold OOF | 0.6019 | 0.7717 | 0.4875 | 0.6171 |

## Local

```bash
pip install -r requirements.txt
# put train.csv in data/raw/
make test                    # 41 tests, ~2 min
make train-fast              # fast_config  -> submissions/submission.csv
make train                   # base_config (slow on a laptop)
python -m src.submission submissions/submission.csv   # re-validate any file
```

## Google Cloud

```bash
make gcp-env       # detect gcloud account/project, write .env (git-ignored)
make gcp-init      # enable Compute+Storage APIs, create gs://sasol-clv-<project>, rsync data/raw
make gcp-run-cpu   # 32-vCPU Spot CPU VM: up -> sync code -> train -> download+validate -> stop
make gcp-run       # same on an L4 GPU VM (T4 fallback across zones) - needs GPU quota
```

Individual steps: `gcp-up`, `gcp-sync-code`, `gcp-train` (streams fold logs and survives SSH drops), `gcp-logs`, `gcp-fetch`, `gcp-down` (stop: compute billing ends, disk kept), `gcp-delete`, `gcp-status`. Prefix any target with `DRY_RUN=1` to print the gcloud plan without running it.

Submissions land in `gs://<bucket>/submissions/<RUN_ID>/` and in local `submissions/`. They are validated before upload and again after download.

GPU quota: new projects usually have 0 `NVIDIA_L4_GPUS`, `NVIDIA_T4_GPUS` and `GPUS_ALL_REGIONS`. That limit also blocks Colab Enterprise and Workbench GPU runtimes, because they draw on the same Compute Engine quota. The dataset (467k lines, ~5k customers per cohort) trains comfortably on CPU, so `GCE_MODE=cpu` is the default in `.env`. Request GPU quota under IAM & Admin → Quotas if you want `make gcp-run`.

## Submission contract

Every file is checked with these assertions before it is written:

- shape is (5488, 4)
- columns are `ID, CLV_fuel, CLV_nonfuel, Opportunity`
- ID order matches `SampleSubmission.csv`
- no NaN values
- CLV predictions ≥ 0
- every Opportunity label is one of the 17 official classes
